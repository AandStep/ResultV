## Что осталось живым (в объём блока не входило)

- **Ссылки `Routing-Lists` на устройстве не гонялись.** Панель impVPN отдаёт
  встроенные xray-правила, а не ссылки; путь со ссылками закрыт Go-тестами.
- **Смена имени панелью на устройстве не проверена** — панель своё имя не
  меняла; поведение закрыто Go-тестами.
- **Тот же дефект опознавания остался на ПК.** `sameRoutingProfile` там
  сравнивает имена, и переименование подписки панелью форкнет профиль. На ПК
  латентно: имя берётся из своего хранилища, а не с провода.

## Грабли, на которые уже наступали

- **AAR не пересобирается сам.** `gradlew assembleDebug` кладёт в APK **старый**
  `.so`. После любой правки Go — `scripts/build-android-aar.sh`, иначе изменения
  молча не приезжают.
- **Скрипт сборки AAR не читает `.env`.** Ключ `SUBSCRIPTION_ENCRYPT_KEY` нужно
  подать окружением: `set -a && source .env && set +a`. Без него собирается AAR,
  который не расшифрует ни одну `resultv://`-ссылку.
- **gomobile молча пропускает** функцию с неподдерживаемой сигнатурой. Успешная
  сборка AAR не доказывает, что биндинг есть; доказывает `javap` по `classes.jar`.
- **Play-флейвор — отдельный AAR.** `libbox-play.aar` легко отстаёт и роняет
  сборку на новых биндингах.
- **Проверять на телефоне, не на 16-килобайтном AVD.** Там любое TLS-действие
  убивает Go-процесс, и выглядит это как «профиль не собирается».
- **Скриншот с этого MIUI** снимается только через
  `adb -s e3bacc6b exec-out screencap -p > file`; круг через `/sdcard` не работает.
- **Имя подписки приезжает как `base64:<UTF-8>`.** Раскодирует его Kotlin
  (`decodePanelTitle`), Go отдаёт как есть. В JVM-тесте `android.util.Base64` —
  заглушка, возвращающая вход, так что раскодирование проверяется только на
  устройстве.
