# Перенос дизайна из Figma

Рабочие материалы редизайна. Источник — Figma `ResultV`, страница
**App UI-kit** (node `0:1`).

## Правило

Дизайн повторяется идентично. Если состояния или значения в макете нет — оно
**не додумывается в коде**, а выписывается в [GAPS.md](GAPS.md) и обсуждается
отдельно.

## Что где лежит

| | |
|---|---|
| [GAPS.md](GAPS.md) | Пробелы и расхождения макета: правки в Figma, вопросы дизайнеру и то, что сделано по своему усмотрению |

| `frontend/src/views/redesign/` | Страницы нового дизайна и их связь с приложением |
| `frontend/src/views/KitShowcase.jsx` | Витрина кита: все компоненты во всех состояниях |

## Куда попадает новая страница

Страница переносится **сразу в приложение**: экран в `views/redesign/`,
подключение во вкладку в `App.jsx`, а `MainLayout` отдаёт таким вкладкам
голую обвязку (свой сайдбар страница рисует сама). Проверяет пользователь
собранным приложением, поэтому «сделал в витрине, встрою потом» не годится.

Перенесены: главная (`home`), добавление сервера (`add`), список серверов
(`list`), умные правила (`rules` — пока только умный режим, см. GAPS).
Остальные вкладки пока на старом виде.

Витрина `kit.html` остаётся песочницей кита и приложением не подключается
(в основной бандл не попадает). Разделы переключаются хешем: без хеша — кит,
`#main` — главный экран, `#add` — добавление сервера.

## Как сверять с макетом

Дев-сервер (`npm run dev`) в этом окружении не работает. Рабочий способ —
собранный фронт и обычный браузер:

```
cd frontend && npm run build
```

`dist/index.html` открывается только внутри Wails, потому что ждёт мост
`window.go`. Для проверки вида его заменяет заглушка: копия `dist` с
дописанным в `<head>` скриптом, который отдаёт `window.go.main.App.*` и
`window.runtime.*` заранее заданные ответы. Дальше — статик-сервер поверх
копии и обычный (или headless) браузер в окне 1000x740.

Внутри самого приложения:

```
wails dev
```

Здесь devtools тоже включены всегда (F12 либо правый клик → Inspect).

Прод-сборка с инспектором — только если нужно посмотреть на собранное
приложение:

```
wails build -tags "with_gvisor,with_utls,with_clash_api,with_quic,with_wireguard,with_naive_outbound,with_purego,with_grpc,devtools"
```

Теги перечислены целиком, чтобы не потерять те, что заданы в `wails.json`.
Релизная сборка (`build-release.sh`) их не использует и остаётся без devtools.

## Проверки

```
cd frontend
npm run verify:icons        # иконки совпадают с макетом
npm run find:icon <хеш>     # какой иконке из @mdi/js соответствует SVG из Figma
```

`find:icon` принимает хеш ассета из ответа `get_design_context`
(`http://localhost:3845/assets/<хеш>.svg`) и ищет совпадение по форме контура,
а не по имени слоя. Нужен запущенный Figma.

## Как берётся следующий кусок макета

1. Ссылка на страницу или секцию → `get_metadata` по id страницы отдаёт дерево
   всех фреймов.
2. Каждый фрейм по отдельности через `get_design_context` (у него ограничение
   на размер ответа, поэтому страница целиком не приходит).
3. Иконки внутри компонентов прогоняются через `find:icon` — своих SVG в
   проекте нет, кроме логотипа и знака Telegram.
4. Всё, чего в макете не хватает, уходит в `GAPS.md`.
