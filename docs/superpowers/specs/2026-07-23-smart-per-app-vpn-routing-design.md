# Smart-режим: пер-аппный роутинг по allowlist + авто-матчинг

**Дата:** 2026-07-23
**Ветка:** android
**Статус:** дизайн согласован, готов к плану реализации

## 1. Контекст и проблема

В Smart-режиме сейчас весь пер-аппный контроль сводится к тому, что **все** приложения находятся в туннеле (denylist: исключён только собственный пакет), а трафик роутится по доменному блок-листу: заблокированный домен → прокси, остальное → `direct` (`internal/proxy/engine.go:781-783,893-903`). Для сайтов это работает: sing-box снимает SNI/Host через `sniff` и отправляет заблокированные домены в прокси.

Две дыры:

1. **Детект VPN.** Приложения вроде Госуслуг ругаются на VPN, даже когда их трафик идёт `direct`, потому что они **видят интерфейс `tun0`**. В Smart их нельзя выкинуть из туннеля: `AppRoutingRepository.disallowedPackages()` возвращает `outOfVpn` только в Global (`android/app/.../vpn/AppRouting.kt:77-78`), а `RuleAction.OutOfVpn` помечен как Global-only.
2. **IP-трафик без SNI.** Доменное правило требует `sniff`. Приложения, ходящие по IP/QUIC без SNI, доменным правилом не ловятся — их заблокированные ресурсы не попадают в прокси. Блок-лист сейчас чисто доменный (`splitSmartDomains`, `internal/proxy/engine.go:747`); IP-подсетей в тракте нет.

## 2. Цель и не-цели

**Цель.** В Smart-режиме приложение по умолчанию **не входит в VPN вообще** (не видит `tun0`), а входит только если система «знает», что оно связано с заблокированными ресурсами — по аналогии с сайтами: изначально есть список, в VPN идёт только то, что в блоке. Всё это — **без ручного ввода в общем случае и без разрывов туннеля**.

**Ключевые свойства:**
- Автоматически прячет VPN от всего длинного хвоста VPN-враждебных приложений (банки, госсервисы, платёжки) — без их курирования.
- Заблокированные приложения (Instagram, YouTube, TikTok, X…) продолжают работать через VPN.
- Браузеры работают всегда (открывают произвольные заблокированные сайты).
- Ручной контроль остаётся escape-hatch'ем: что авто-логика пропустила — пользователь добавляет/исключает сам.

**Не-цели:**
- Не трогаем Global-режим: там остаётся denylist (`addDisallowedApplication`), вкладки `[из VPN, запретить]`, `final=proxy`.
- Не строим динамическую перестройку членства «на лету» (это = разрыв туннеля). Членство считается один раз при поднятии туннеля.
- Не курируем полный список «заблокированных приложений» на 86k — используем уже имеющийся доменный блок-лист + матчинг.

## 3. Модель

### Два независимых слоя (не путать)

| Слой | Гранулярность | Механизм | Роль |
|------|---------------|----------|------|
| **Членство в туннеле** | приложение (пакет) | Smart → `addAllowedApplication` (allowlist); Global → `addDisallowedApplication` (denylist) | видит ли приложение VPN вообще |
| **Роутинг внутри туннеля** | домен / IP | route-правила sing-box по блок-листу | что из того, что *в* туннеле, идёт в прокси |

### Членство в Smart (allowlist)

Android-ограничение: `addAllowedApplication` и `addDisallowedApplication` **взаимоисключающие** на одном `Builder`. Режим выбирает механизм.

Smart-allowlist (множество пакетов, которые кладём в туннель) вычисляется при поднятии туннеля:

```
allowlist = ( auto_matched ∪ browsers ∪ intoVpn ) − outOfVpn − ownPackage
```

- `auto_matched` — приложения, чьё имя пакета/label совпало с брендом из доменного блок-листа (см. §6).
- `browsers` — приложения, обрабатывающие http `ACTION_VIEW`/`CATEGORY_BROWSABLE` (определяются через `PackageManager`).
- `intoVpn` — ручное включение (существующий список, вкладка «в VPN»): «загнать это приложение в VPN, даже если авто-логика его не взяла».
- `outOfVpn` — ручное исключение (существующий список): «никогда не гнать это приложение в VPN». Действует в **обоих** режимах — то есть в Smart тоже убирает приложение из allowlist. Это ровно эффект «как в Global добавить в из-VPN».
- `ownPackage` — наш пакет никогда не в туннеле (иначе рекурсия при дозвоне до прокси); в allowlist это достигается тем, что мы его просто не добавляем.

Всё, что не попало в allowlist, — вне туннеля → `direct` → VPN не видит.

**Гард на пустоту.** Если вычисленный allowlist пуст (нет браузеров и совпадений), поднимать туннель с пустым allowlist нельзя — он не понесёт ничего. Fallback: если браузеров не нашлось и совпадений нет, откатываемся на denylist-поведение (все в туннеле, исключая `outOfVpn` + `ownPackage`), чтобы Smart не стал «no-op». Браузер на устройстве есть практически всегда, так что это чисто страховка.

### Роутинг в Smart (без изменений в принципе, + IP)

Внутри туннеля роутинг остаётся прежним: блок-лист по домену → прокси, `final=direct`. Добавляется параллельная ветка по IP (§7): заблокированный IP/CIDR → прокси, срабатывает **до** `sniff` (чистый IP, SNI не нужен) — это и ловит IP/QUIC-приложения.

`intoVpn`-приложения дополнительно получают package_name-правило `→ proxy` (уже есть, `mobile/libbox.go:836-848`): весь их трафик в прокси, не только заблокированный.

### Global — не меняется

Denylist, `final=proxy`, вкладки `[из VPN, запретить]`. `outOfVpn` исключает через `addDisallowedApplication` (как сейчас).

## 4. Архитектура и компоненты

### Kotlin

- **`SmartAppMatcher.kt` (новый, чистый, JVM-тестируемый).** Вход: список установленных приложений (пакет, label), множество «брендов» из блок-листа, таблица алиасов, множество браузеров. Выход: множество авто-включённых пакетов. Никакого `Context` — по образцу `AppRules.kt` (тестируется без Robolectric). Ядро матчинга — §6.
- **`AppTunnelMembership` (новый, чистый).** Собирает финальный allowlist по формуле из §3 из четырёх множеств (`auto_matched`, `browsers`, `intoVpn`, `outOfVpn`) + `ownPackage`, с гардом на пустоту. Отдельно от матчера, чтобы алгебра множеств и матчинг тестировались независимо.
- **Определение браузеров** (в репозитории приложений, требует `Context`): `PackageManager.queryIntentActivities` по `Intent(ACTION_VIEW, "http://")` c `CATEGORY_BROWSABLE`. Кэшируется на время сессии.
- **Таблица алиасов** — маленький встроенный ресурс `pkg → домен-бренд` для ребрендов/коротышей (`com.twitter.android → x.com`, `org.telegram.messenger → t.me`, `com.zhiliaoapp.musically → tiktok.com` если label не вытянет). Обновляемая с инфры проекта тем же путём, что доменные источники (env-override), но со встроенным сидом.
- **`SmartListRepository.kt`** — расширяется полем `ips: List<String>` в `Snapshot`, парсит `ips` из ответа `FetchSmartList`, персистит в мете, отдаёт `toEngineIPList()` (newline). Также предоставляет доменные «бренды» для матчера (набор SLD-меток из `domains`).
- **`AppRouting.kt`** — `disallowedPackages(mode)` в Global без изменений; для Smart появляется `allowedPackages(...)` (или membership отдаётся через `AppTunnelMembership`).
- **`BoxModule.kt` / `BoxPlatform.applyAppRouting`** — ветвление по режиму: Global → `addDisallowedApplication` (как сейчас); Smart → `addAllowedApplication` по вычисленному allowlist. Собственный пакет в Smart просто не добавляем.
- **`RuleAction.kt`** — обновить doc-комментарий про `OutOfVpn`: теперь действует в обоих режимах.
- **UI `RulesScreen.kt`** — §8.

### Go / движок (общий с десктопом)

- **`internal/proxy/blocked_provider.go`** — добавить IP/CIDR-источник(и) для RU рядом с доменными; классифицировать записи (`net.ParseIP`/`net.ParseCIDR`) на домены vs IP; вернуть оба набора. `BlockedDomainsCache` получает поле `ips []string` (старые кэши без него → пусто, обратная совместимость).
- **`internal/proxy/engine.go`** — `EngineConfig` получает `SmartBlockedIPs []string`; `buildRoute` в Smart добавляет правило `IPCidr → proxy` **до** `sniff`, но **после** правил `server-IP → direct` и bypass-LAN (первое совпадение выигрывает, порядок сохраняет корректность).
- **`mobile/libbox.go`** — `BuildOptions` получает `SmartBlockedIPsList string` (newline-separated); новый сплиттер; проброс в `EngineConfig.SmartBlockedIPs`. `FetchSmartList` возвращает `ips` в JSON.

## 5. Поток данных (connect path)

1. Пользователь в Smart, жмёт «Подключить».
2. `SmartListRepository.ensureLoaded()` даёт снапшот: `domains` + `ips`.
3. Kotlin вычисляет:
   - `browsers` ← `PackageManager`.
   - `auto_matched` ← `SmartAppMatcher(installedApps, brands=SLD(domains), aliases, browsers)`.
   - `allowlist` ← `AppTunnelMembership(auto_matched, browsers, intoVpn, outOfVpn, ownPkg)`.
4. `BuildOptions` собирается с `SmartMode=true`, `SmartBlockedDomainsList`, `SmartBlockedIPsList`, `IntoVpnApps`, `BlockedApps` (как сейчас, `outOfVpn` в конфиг движка не идёт — он применяется на уровне OS).
5. `BoxPlatform.openTun` → в Smart `addAllowedApplication(pkg)` по `allowlist`.
6. Движок: доменные + IP правила отправляют заблокированное в прокси, `final=direct`.

Пересчёт членства происходит **только** при (пере)поднятии туннеля. Обновление блок-листа или установка нового приложения применяются на следующем подключении — **без разрыва** текущей сессии (принято как компромисс, соответствует «без разрывов»).

## 6. Матчер (пакет + label + алиасы)

**Бренды из блок-листа.** Из `domains` берём second-level label (`youtube.com → youtube`, `instagram.com → instagram`), собираем множество `brands` (только метки длиной ≥ 3, чтобы отсечь шум типа `x`, `t`, `vk` матчим через алиасы).

**Кандидаты приложения.** Из пакета берём сегменты (`com.google.android.youtube → {google, android, youtube}`, служебные `com/org/net/android/app` в стоп-лист), из label — слова (нормализованные: lowercase, без пробелов/символов; `TikTok → tiktok`).

**Матч.** Приложение авто-включается, если пересечение его кандидатов с `brands` непусто, ИЛИ его пакет есть в таблице алиасов и алиас-бренд ∈ `brands`.

**Известные пределы (документируем, лечим алиасами/ручным добавлением):**
- Обфусцированные пакеты без бренд-токена в пакете вытягиваются через **label** (`TikTok`↔tiktok.com) — это главный усилитель recall.
- Ребренды/коротыши (`x.com`, `t.me`) — через **таблицу алиасов**.
- Приложения, ходящие только на не-бренд CDN/бэкенд-домены → не сматчатся → ручное «в VPN».
- Ложные срабатывания (пакет/label случайно совпал с бренд-меткой) → приложение окажется в туннеле лишний раз (низкий вред: только его заблокированный трафик и так в прокси; может увидеть VPN). Порог длины ≥ 3 и стоп-лист сегментов снижают шум.

**Остаточный принятый кейс:** не-браузерное, не-сматченное, не-алиасное приложение, которому нужен заблокированный ресурс, не работает, пока пользователь не добавит его в «в VPN». Ограничено и восстановимо вручную.

## 7. IP-поддержка (пайплайн)

```
источник IP-листа (RU)                          [blocked_provider.go]
   → классификация домен/IP (ParseIP/ParseCIDR)  [blocked_provider.go]
   → BlockedDomainsCache{ domains, ips }          [blocked_provider.go]
   → FetchSmartList JSON { domains, ips }          [mobile/libbox.go]
   → SmartListRepository.Snapshot{ domains, ips }  [Kotlin]
   → BuildOptions.SmartBlockedIPsList (newline)    [Kotlin → JNI]
   → EngineConfig.SmartBlockedIPs                  [mobile/libbox.go]
   → route rule { ip_cidr → proxy } до sniff       [engine.go buildRoute]
```

Правило `ip_cidr → proxy` в Smart ставится после `server-IP → direct` и bypass-LAN, до `sniff`. Пустой IP-набор → правило не эмитится (как с доменами).

## 8. UI (RulesScreen)

**Global** — без изменений: `[из VPN, запретить]`.

**Smart** — раздел «приложения» показывает эффективное членство и позволяет override в обе стороны, без добавления третьей вкладки-«из VPN»:

- Каждая строка приложения показывает **авто-состояние**: «авто: в VPN» (сматчено/браузер) или пусто (по умолчанию вне VPN).
- Чекбокс «в VPN» отражает **эффективное** состояние (авто ∪ ручное − исключения):
  - отметить приложение, которое авто-логика не взяла → добавить в `intoVpn`;
  - снять отметку с авто-включённого (например, браузер, который не нужен в VPN) → добавить в `outOfVpn` (ручное исключение, действует в обоих режимах);
  - вернуть в авто-состояние → убрать из соответствующего ручного списка.
- Вкладка «запретить» (`Block`) — без изменений.

Так «дизайн остаётся как есть» по духу (в Smart основное действие — «в VPN»), но появляется возможность и исключить авто-включённое. Строка-бейдж «авто: в VPN» делает решение системы прозрачным.

> **Решение на ревью спеки:** переиспользуем существующий `outOfVpn` как общий список исключений для обоих режимов (проще, единая ментальная модель «из VPN = никогда не туннелировать»). Побочный эффект: исключив браузер в Smart, пользователь исключает его и в Global. Считаю это ожидаемым; если нужна независимость режимов — заведём отдельный `smartExcluded` набор.

## 9. Крайние случаи и режимы отказа

- **API < 29.** Членство через `addAllowedApplication`/`addDisallowedApplication` работает на всех уровнях; матчинг — чистый Kotlin. Значит авто-исключение VPN-враждебных приложений работает и ниже API 29. `intoVpn` force-proxy и `Block` (package_name-правила) по-прежнему требуют API 29 (`findConnectionOwner`), как сейчас.
- **Пустой allowlist** → fallback на denylist-all (см. §3).
- **Установка приложения при активном туннеле** → применится на следующем подключении (без разрыва). Опционально: подсказка «переподключитесь, чтобы применить».
- **Заблокированное приложение, которое само детектит VPN** (редко) → в туннеле, может ругаться; лечится ручным исключением.
- **Блок-лист пуст на первом коннекте** → в Smart `final` держит Global-поведение (`engine.go:781`); allowlist тогда = браузеры ∪ intoVpn − outOfVpn (матчинг по пустым брендам ничего не даёт). Приемлемо: соединение поднимается, авто-матчинг доедет после фонового `refresh()`.

## 10. Миграция и совместимость

- Модель данных `AppRulesState` (`outOfVpn/intoVpn/blocked`) структурно не меняется — переиспользуем существующие списки. Миграции файла не нужно.
- `BlockedDomainsCache` без `ips` → пустой IP-набор.
- `BuildOptions.SmartBlockedIPsList` опционально; пусто → доменное поведение как раньше.
- Global-путь байт-в-байт прежний.

## 11. Тестирование

**Kotlin (JVM, без Robolectric):**
- `SmartAppMatcher`: совпадение по пакету; совпадение по label при обфусцированном пакете (TikTok); алиас (X, Telegram); ложное срабатывание отсекается порогом/стоп-листом; служебные сегменты игнорируются.
- `AppTunnelMembership`: композиция allowlist; `intoVpn` включает; `outOfVpn` исключает и переопределяет авто/`intoVpn`; `ownPackage` всегда вне; гард пустоты → fallback.

**Go:**
- `engine_smart_test.go` (расширить): в Smart эмитится `ip_cidr → proxy` до `sniff` и после server-IP/bypass-LAN; пустой IP-набор → нет правила; Global не эмитит IP-smart-правило.
- `blocked_provider`: классификация домен vs IP/CIDR; кэш round-trip с `ips`; старый кэш без `ips` читается.
- `libbox`: сплиттер IP-листа; проброс в `EngineConfig`.

**Ручная проверка на устройстве:**
- Smart + Госуслуги → приложение вне туннеля, не ругается, VPN не детектит.
- Smart + Instagram/YouTube/TikTok → работают через VPN (авто-матч; TikTok через label/алиас).
- Smart + браузер + заблокированный сайт → открывается.
- Ручное «в VPN» для нарочно не-сматченного приложения → начинает работать.
