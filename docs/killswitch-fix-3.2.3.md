# Kill Switch — исправление ложных срабатываний (3.2.3)

## Проблема

В прокси-режиме без прав администратора kill switch срабатывал спустя ~2 минуты после подключения, хотя сервер был рабочим и интернет не пропадал. В туннельном режиме с правами администратора такого не наблюдалось — там kill switch срабатывал только при реальном падении сервера.

## Корневые причины

### 1. Неправильная проба соединения в прокси-режиме

Watchdog здоровья соединения (`runHealthWatchdog`) каждые **5 секунд** дёргал `net.DialTimeout("tcp", ip:port, 5s)` — голый TCP-коннект к порту прокси-сервера без передачи данных.

**Последствия:**
- Для сервера это выглядит как сканирование портов. Серверы за nginx/fail2ban/SYN-cookies через пару минут начинают дропать такие SYN-пакеты, хотя реальный трафик через уже установленные соединения продолжает ходить нормально.
- Если `proxy.IP` — это домен (CDN, подписки), каждая проба заново резолвила его через системный DNS. Без прав администратора DNS-override не применяется, и резолв идёт через DNS провайдера, который нередко троттлит частые повторяющиеся запросы → два промаха подряд → ложный «сервер мёртв».

### 2. Аварийный попап не зависел от наличия прав администратора

`KillSwitchEmergency = proxyDead && killSwitch`

Аварийное окно всплывало при любых условиях — даже когда без прав администратора OS firewall физически не мог заблокировать трафик. Пользователь получал блокирующий алерт «Kill Switch сработал», хотя ничего заблокировано не было.

### 3. Слишком агрессивные параметры watchdog

- Интервал: **5 секунд** — зондирование почти 1 раз в 5 секунд
- Порог: **2 промаха подряд** — достаточно одного кратковременного сбоя сети, GC-паузы на сервере или потери пакета

### 4. Почему туннельный режим работал корректно

Туннельный режим требует прав администратора (без них вообще не запускается). Следовательно:
- DNS-override всегда применён — нет ложных DNS-промахов
- Firewall реально встаёт → срабатывание = реальный инцидент
- Проба — LAN-bind к серверу, не подверженная server-side rate-limit

## Что исправлено

### `internal/proxy/manager.go`

#### Новая функция `probeProxyHealth`

В прокси-режиме watchdog теперь проверяет соединение **через локальный листенер sing-box** (`127.0.0.1:localPort`), а не голым TCP к серверу:

```go
func probeProxyHealth(localPort int) bool {
    // HTTP-запрос через 127.0.0.1:localPort к connectivity-check эндпоинтам
    // Любой HTTP-ответ (кроме 407) = туннель работает
}
```

**Преимущества:**
- Неотличимо от обычного проксируемого трафика — нет триггера rate-limit
- Домен резолвится удалённо через sing-box, а не локальным (ISP) DNS
- Реально проверяет data path: sing-box → upstream → выход

#### Диспетчер `probeHealthy`

```go
func (m *Manager) probeHealthy(proxy ProxyConfig, mode ProxyMode, localPort int, engineRunning bool) bool {
    if mode == ProxyModeProxy && engineRunning && localPort > 0 {
        return probeProxyHealthProbe(localPort)
    }
    return m.probeProxyAlive(proxy, mode) // fallback: прямая достижимость сервера
}
```

Fallback на прямую достижимость используется в двух случаях:
- Туннельный режим (LAN-bind проба, поведение не изменилось)
- Прокси-fallback путь, когда sing-box не запустился и системный прокси указывает прямо на сервер (локального листенера нет)

#### Разные параметры watchdog по режимам

| Параметр | Прокси-режим | Туннельный режим |
|---|---|---|
| Интервал | 10 с | 5 с |
| Порог промахов | 3 | 2 |

Туннельный режим оставлен без изменений — LAN-bind проба надёжна, и там firewall реально блокирует трафик, поэтому быстрая детекция важнее.

#### Поле `isAdmin` — кеш прав администратора

```go
// Manager
isAdmin bool

// Init()
m.isAdmin = isAdminCheck()
```

`IsAdmin()` на Windows запускает `net session` — вызов не бесплатный. Кешируется один раз при старте вместо дёргания на каждом тике watchdog.

#### Kill switch engage только при наличии прав

```go
switch {
case ks && m.isAdmin && m.KillSwitchFirewallEngage != nil:
    // Firewall реально блокирует трафик
    m.log.Warning("[KILL SWITCH] VPN-сервер недоступен — kill switch блокирует весь трафик")
    shouldEngage = true
    ...
case ks && !m.isAdmin:
    // Только лог — firewall не встанет, попап не нужен
    m.log.Warning("[KILL SWITCH] VPN-сервер не отвечает. Блокировка трафика недоступна без прав администратора...")
default:
    m.log.Warning("[PROXY] VPN-сервер недоступен")
}
```

#### `KillSwitchEmergency` требует прав администратора

```go
// Было:
KillSwitchEmergency: m.proxyDead && m.killSwitch,

// Стало:
KillSwitchEmergency: m.proxyDead && m.killSwitch && m.isAdmin,
```

Без прав администратора `IsProxyDead` по-прежнему выставляется (пользователь видит, что сервер не отвечает), но блокирующий аварийный попап не поднимается.

## Дополнение: ложное срабатывание в туннельном режиме

Первая версия 3.2.3 исправила только прокси-режим. Однако ложное срабатывание
воспроизвелось и в **туннельном режиме** с правами администратора (Hysteria2):
kill switch сработал, firewall реально встал и тут же снялся в течение ~1 секунды —
сервер был жив всё время.

### Корневая причина (та же, но для туннеля)

`probeHealthy` в туннельном режиме для каждого протокола открывал **новое**
соединение к серверу:

- Hysteria2 → `PingHysteria2QUICLANBind` (полное QUIC-рукопожатие, timeout 3 с)
- WireGuard/AmneziaWG → `PingProxyUDPLANBind`
- TCP-протоколы → `PingProxyLANBind`

Два тайм-аута подряд (≤10 с) → kill switch, даже когда существующая сессия
исправно гоняет трафик. Новое соединение могло транзитно не подняться
(server-side rate-limit, потеря UDP-пакета, GC-пауза), хотя туннель работал.

### Исправление

Добавлена `probeTunnelHealth()` — HTTP-запрос к connectivity-check эндпоинтам
через TUN-интерфейс (домены принудительно идут через прокси-outbound по правилам
роутинга sing-box). `probeHealthy` теперь для туннельного режима с запущенным
движком проверяет **реальный data path** этой пробой — для **всех** протоколов,
а не открывает новое соединение к серверу.

Прямая проба сервера (`probeProxyAlive`) остаётся fallback'ом только когда движок
не запущен.

| Сценарий | До фикса | После фикса |
|---|---|---|
| Туннель, есть права, сервер живой | Ложный kill switch при сбое новой пробы | Нет ложных срабатываний, проверяется data path |
| Туннель, есть права, сервер упал | Попап + firewall | Попап + firewall (без изменений) |
