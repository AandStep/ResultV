## 1. Идентификаторы сборки

| Поле | Значение | Откуда |
|---|---|---|
| Package name | `com.resultv.android` | `android/app/build.gradle.kts` |
| versionName / versionCode | `1.2.0` / `10200` | там же; в релизе переопределяются из тега `android-v*` |
| minSdk / targetSdk | 26 / 36 | там же |
| Формат артефакта | AAB, `DIST=play bash build-android.sh release` из корня | см. ниже |
| Путь | `android/app/build/outputs/bundle/playRelease/app-play-release.aab` | |
| ABI в бандле | `arm64-v8a`, `armeabi-v7a` (x86 отсутствуют) | замер `unzip -l` |
| Выравнивание `.so` | `LOAD align = 0x4000` (16 КБ) | `llvm-readelf -lW`, перемерено 2026-10-13 |
| Подпись | Play App Signing; загрузочный ключ — `android/release.keystore` (`CN=ResultV`, RSA 2048, до 2053), реквизиты в `keystore.properties` (в `secrets.enc`) | `keytool -list -v` |

**Дистрибутив.** В магазин уходит флейвор `play`. Он собран из отдельного AAR
(`libbox-play.aar`, теги `no_mitm,no_adblock`) и не содержит ни MITM, ни
DNS-фильтрации — см. раздел 6.

**Сборка только скриптом и только локально.** CI (`release-android.yml`)
собирает лишь `full`, play-AAR в нём не строится. Голый
`./gradlew bundlePlayRelease` берёт тот `libbox-play.aar`, что лежит в
`android/libs`, а он легко отстаёт от Go: на 2026-10-13 AAR был от 17.09, за
ним девять коммитов в Go. `build-android.sh` пересобирает AAR и подтягивает
`SUBSCRIPTION_ENCRYPT_KEY` из `.env`; без ключа сборка проходит, но импорт
`resultv://` в ней сломан — скрипт об этом предупреждает строкой
`SUBSCRIPTION_ENCRYPT_KEY not set`.

**NDK 28+.** С 2026-10-13 в сборку входит NaiveProxy (Cronet), и
`scripts/build-android-aar.sh` отказывается работать на NDK младше 28:
`libcronet.a` не линкуется ld.lld из NDK 27. Локально стоит NDK 30, в CI —
r28. `.so` выросла на ~18 МБ на архитектуру (arm64: 80 МБ внутри AAB),
выравнивание 16 КБ сохранилось.

### 1.1 Ключ подписи приложения — решить до первой загрузки

`full` с сайта и `play` из магазина — один `applicationId`
(`com.resultv.android`). Если при включении Play App Signing согласиться на
ключ, сгенерированный Google, подписи сборок разойдутся, и Android откажет в
установке поверх: пользователь сайта не обновится из Play и наоборот, только
через удаление с потерей профилей. Это решение необратимо.

Варианты:

- **Загрузить свой ключ** (`release.keystore`) как ключ подписи приложения —
  в консоли пункт про экспорт и загрузку ключа из Java keystore (утилита
  PEPK). Обе сборки остаются взаимозаменяемыми.
- **Развести пакеты**: `applicationIdSuffix` у одного из флейворов. Тогда
  ключ Google допустим, но на телефоне будут два разных приложения.

## 2. Форма VpnService (App content → Declarations)

Play требует отдельную декларацию от каждого приложения, использующего
`VpnService`. Факты для ответов:

- **Основная функция.** Клиент VPN. Пользователь подключается к собственным
  серверам: вводит ссылку на сервер или URL подписки своего провайдера.
  Приложение не владеет серверами и не продаёт трафик — в нём нет ни встроенных
  серверов, ни бесплатного пула, ни регистрации.
- **Используется ли VPN только для основной функции.** Да. Единственный
  `VpnService` — `com.resultv.android.vpn.ResultVpnService`
  (`AndroidManifest.xml:81`), туннель поднимается только по явному действию
  пользователя и по системному диалогу `VpnService.prepare()`.
- **Собирает ли приложение данные пользователей через VPN.** Нет. Трафик
  проходит на сервер, указанный пользователем; приложение его не пишет, не
  анализирует и никуда не отправляет. Локально ведётся только счётчик
  переданных байт (`DataUsageRepository`) и журнал событий движка (`AppLog`),
  оба — на устройстве.
- **Манипулирует ли рекламой.** Нет. В магазинной сборке фильтрации нет вовсе
  (раздел 6) — это проверяемо распаковкой бандла.
- **Есть ли реклама в самом приложении.** Нет.

## 3. FOREGROUND_SERVICE_SPECIAL_USE

Манифест объявляет `android:foregroundServiceType="specialUse"` и свойство
`android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE` со значением `VPN tunnel`
(`AndroidManifest.xml:84,87`). Для `specialUse` Play требует обоснования в
консоли. Содержание обоснования:

> Приложение — клиент VPN. Туннель поднимается через `VpnService` и обязан
> жить, пока пользователь его не выключит: обрыв foreground-сервиса означает
> разрыв соединения и потерю защиты трафика. Ни один из типизированных
> foreground-типов Android 14 (`dataSync`, `mediaPlayback`, `location` и т. д.)
> не описывает работу VPN-туннеля, поэтому используется `specialUse` с
> подтипом `VPN tunnel`. Сервис запускается только после явного согласия
> пользователя в системном диалоге `VpnService.prepare()` и останавливается по
> его команде, по kill switch или при остановке системой.

## 4. Разрешения и видимость приложений

Весь список (`AndroidManifest.xml:4-7`):

| Разрешение | Зачем |
|---|---|
| `INTERNET` | сетевые соединения движка и загрузка подписок |
| `FOREGROUND_SERVICE` | туннель как foreground-сервис |
| `FOREGROUND_SERVICE_SPECIAL_USE` | см. раздел 3 |
| `POST_NOTIFICATIONS` | уведомление о состоянии туннеля (единственное runtime-разрешение) |

Опасных разрешений нет. `QUERY_ALL_PACKAGES` **убран** (коммит `15730f1`) и
заменён на `<queries>` с фильтрами `MAIN/LAUNCHER` и `VIEW http` — первый
питает пикер per-app маршрутизации, второй нужен `AppInventory.browserPackages`
для определения браузеров. Если ревьюер спросит про видимость приложений: она
нужна, чтобы пользователь мог выбрать, какие приложения пускать в туннель, а
какие нет; список приложений никуда не отправляется.

Сканер QR берётся из `play-services-code-scanner`: модуль догружается Play
Services, разрешение `CAMERA` приложению не нужно и не запрашивается.

## 5. Data safety

Аналитики, крашлитики и рекламных SDK в проекте нет — проверено грепом по
`firebase|crashlytics|analytics|appmetrica|sentry|amplitude`, совпадений ноль.

**Что уходит с устройства и куда:**

| Данные | Куда | Обязательно | Примечание |
|---|---|---|---|
| HWID — хеш `ANDROID_ID` с солью (`config.HashHWIDSource`), заголовок `x-hwid` | **только** на URL подписки, который ввёл пользователь | нет — тумблер «Передавать HWID», **включён по умолчанию** | `SettingsRepository.subscriptionSendHwid`, `mobile/libbox.go` |
| `x-device-os`, `x-ver-os`, `x-device-model` (производитель + модель), User-Agent | туда же | **да** — тумблер HWID их не выключает | `subscriptionDeviceHeaders` в `mobile/libbox.go`; панели Happ/Remnawave показывают их в списке устройств |
| IP-адреса серверов пользователя (домен резолвится на устройстве), параметр `?ip=` | `result-proxy.ru/countryAPI/api.php` — **сервер разработчика** | да — для флагов стран | `CountryRepository` → `Mobile.detectCountry` → `internal/proxy/country.go` |
| Запрос страны без параметров (страна по IP пользователя) | `result-proxy.ru/countryAPI/api.php` | только если регион Smart не выбран вручную | `FetchSmartList` с пустой страной → `ResolveCountry` |
| HTTP-запрос за списками маршрутизации Smart | `raw.githubusercontent.com`, `cdn.jsdelivr.net` | нет — только при включённом Smart | пользовательских данных не содержит |
| Списки и профили маршрутизации | URL, добавленные пользователем или провайдером | нет | пользовательских данных не содержит |
| Диагностика сканера QR (модель, ОС, версия приложения, метрики, коды ошибок, ID установки) | Google (ML Kit, `play-services-code-scanner`) | только при открытии сканера | https://developers.google.com/ml-kit/android-data-disclosure |
| Проверка связности | `www.gstatic.com/generate_204` | да | стандартная проверка, тела нет |
| Трафик пользователя | сервер, который выбрал пользователь | да | это и есть функция приложения |

**Что хранится только на устройстве:** профили серверов, подписки, настройки,
правила маршрутизации, журнал (`AppLog`), счётчики трафика. Облака у
приложения нет, аккаунтов нет, восстановления нет.

Отсюда ответы в анкете Data safety:

| Тип данных (Play) | Collected / Shared | Обязательно | Цель |
|---|---|---|---|
| Device or other IDs — HWID | Collected | Optional | App functionality (лимит устройств у провайдера) |
| Device or other IDs — ID установки ML Kit | Collected | Required при использовании сканера | Analytics (диагностика Google) |
| App info and performance → Diagnostics (ML Kit) | Collected | Required при использовании сканера | Analytics |
| Location → Approximate location — IP при определении страны | Collected | Required | App functionality |

- **Shared — нет.** Передача на панель подписки инициирована пользователем
  (он сам вводит её URL) — это исключение «user-initiated transfer»; ML Kit
  по заявлению Google данные третьим лицам не передаёт.
- Модель и версия ОС отдельного типа в анкете не имеют; они описаны в
  политике и входят в «Device or other IDs» по смыслу.
- Шифрование при передаче — да (HTTPS везде, `countryAPI` отвергает http).
- Удаление — сносом приложения; записи `countryAPI` в журнале сервера — по
  запросу на e-mail из политики.

## 6. Чего в play-сборке нет (и как это показать)

Это самое важное для ревью и единственное, что проверяется машинным способом.

- **Браузерный ad-block (MITM + пользовательский корневой CA)** — вырезан тегом
  `no_mitm`. `internal/filter` отсутствует в зависимостях, маркер `gomitmproxy`
  в `libgojni.so`: full 21 → play 0.
- **DNS-фильтрация** — вырезана тегом `no_adblock` (коммит `b2e2d77`). Списки
  `adblock_reject.srs` и `geosite-category-ads-all.srs`, а также зашитые
  рекламные домены больше не попадают в бинарь: маркеры
  `adblock_reject.srs`, `category-ads-all`, `pubserv.pro`, `foxstreetcore.com`,
  `adultmasters.pro`, `googlesyndication.com`, `doubleclick.net`, `2mdn.net` —
  full 2/2/3/3/3/2/3/1 → play 0.

**С 2026-10-13 `doubleclick.net` в play = 1, и это не регрессия.** В сборку
вошёл NaiveProxy, а с ним Cronet — сетевой стек Chromium. Единственное
вхождение — строка из его кода разбора URL (по соседству
`Trying to get the spec of an invalid URL!`), а не элемент списка блокировки.
Остальные маркеры по-прежнему 0. Если ревьюер спросит — ответ этот.

Воспроизвести замер:

```bash
unzip -o -j android/libs/libbox-play.aar 'jni/arm64-v8a/libgojni.so' -d /tmp/play
for m in gomitmproxy adblock_reject.srs category-ads-all pubserv.pro; do
  printf '%-22s %s\n' "$m" "$(grep -c -a -o "$m" /tmp/play/libgojni.so)"
done   # ожидается 0 по каждому
```

**Про crypto/rand.** На эмуляторе Android 17 beta (ядро 6.12, страницы 16 КБ)
любое Go-приложение падает на `crypto/rand` из-за vDSO `getrandom`,
возвращающего EFAULT; это баг Go, воспроизведён вне нашего кода, обходного пути
без патча stdlib нет. Наши целевые устройства сегодня иммунны (ядра младше
6.11), но телефоны на GKI 6.12 — нет. Если pre-launch report покажет этот крэш,
решение придётся пересматривать.
